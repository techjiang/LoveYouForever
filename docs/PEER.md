# 双站互连

两个人各跑一套「永远爱你」，两台机器，两个数据库。
这篇讲清楚它们怎么互相看得见，以及为什么是这么设计的。

## 先分清两件事

| | 是什么 | 能不能关 |
|---|---|---|
| **情侣关系** | 你们是谁，绑在哪个账号上 | **永远不能**，这是项目的核心设定 |
| **双站互连** | 要不要互相看得见对方的内容 | 想关就关 |

这两件事在代码里也是分开的：关系在 `app/services/couple_service.py`，
互连在 `app/services/peer_service.py`。关掉互连一个字节都不会碰到关系表。

后台那句提示是特意写的：**断开互连 ≠ 解绑**。这是最容易被误会的地方。

## 怎么连

1. 两台机器各自完成情侣绑定（互连要求双方都 `bound`）
2. 两边都去「站点设置 → 基本信息」把**站点地址**填对 —— 互连靠它认人
3. 任意一边：后台 →「双站互连」→ 填对方地址 → 连接
4. 点「立刻同步」

后台会显示一个**互连令牌**（32 位）。把它发给对方，让对方在连接时填上，
这样别人就拉不走你们的内容了。不填也能连，只是不设防。

命令行也一样：

```bash
flask peer --url https://ta.example.com --token 对方的令牌 --sync
```

## 同步了什么，没同步什么

**出去的：**

- 瞬间 —— 只有 `is_public=True` 的
- 文章 —— 只有 `status="published"` 的
- 约定 —— 文字和签署状态
- 纪念日 —— 名字、日期、备注

**出不去的：**

- 隐藏的瞬间（`is_public=False`）
- 草稿
- 小纸条（`Note`）
- 用户、密码、`SECRET_KEY`、站点设置

规则写在 `peer_service.outgoing_*` 这几个函数里，不在视图里 ——
以后加接口的人没法「不小心」把私密内容漏出去。

## 图片为什么要转发

对方站上的图，不是直接用它的 URL，而是通过本机的
`/couple/images/<32位缓存名>` 转出去。三个原因：

1. **HTTPS 页面里不能引 HTTP 的图**，浏览器会直接拦掉
2. 对方的图片地址可能带签名、会过期
3. 对方换域名、关站，你这边整页图全挂

`/couple/images/<name>` 只接受 `[0-9a-f]{32}.扩展名` 这个形状的文件名。
用户可控的路径直接拼进文件系统就是目录穿越，这条线必须卡死。

## 同步是只读的

镜像内容存在 `peer_mirrors` 表里，带 `kind` + `remote_id` 唯一约束，
同步多少次都只有一行。这些内容**不能**在本机编辑 ——
对面那台机器不在我们手上，我们没资格替它改数据。

管理后台只提供「清空镜像内容」，不提供「编辑」。

## 出问题了

**连不上**

后台点「探一下对方」，会显示具体原因。常见的是：

- 站点地址填错，或者带了路径（只认 `scheme://host:port`）
- 对方的地址从公网访问不到（内网机器之间互连是可以的）
- 对方还没绑定情侣关系 —— 这种会被明确拒绝

**连上了但没内容**

点「立刻同步」。如果对方那边确实有公开的瞬间，还是空的话：

- 对方站可能把瞬间设成了「不公开」
- 对方的 `/couple/peer/moments` 返回非 200，用对方后台的「探一下」确认

**令牌对不上**

对方改了站点地址或换了密钥，令牌就会变，重新要一次。

## 自己跑一遍（不用两台机器）

```bash
flask seed --with-partner
flask peer-demo
```

`peer-demo` 会在本机造一个假的「对方站点」，往镜像表里写一批演示内容 ——
**不联网**。打开后台或情侣页就能看到效果。清掉：

```bash
flask peer-demo-clear
```

这是给演示和自测用的，正式站要连真站点，用 `flask peer`。
